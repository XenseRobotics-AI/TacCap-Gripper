## 3. 已有实机证据

用户完成三轮空夹爪测试：`empty-baseline`、`empty-motion`、`empty-high-frequency`。
原始记录在工作区 `sine-runs/`（实验输出不随 SDK 源码版本管理交付）。
以下保留可随仓库阅读的结果摘要，复现采集 / 分析方法见[正弦工具说明](../SINE_SWEEP.md)。

高频轮的条件：SDK 0.1.11、固件 1.1.8、原标定行程 1.225934 rad、闭合补偿 0.03 rad，
目标中心 0.5 / 半幅 0.25，参考速度 7.5 rad/s，输入与反馈配置 100 Hz。
每组合预热 2 周期、测量 8 周期，每组合仅一次，共 20 组。

RMSE 为相对于补偿后期望电机位置的误差，占原标定行程的百分比：

| 正弦频率 | 请求 0.35 Nm | 请求 0.6 Nm | 请求 0.9 Nm | 请求 1.2 Nm |
|---|---|---|---|---|
| 0.25 Hz | 0.65% | 0.71% | 0.64% | 0.58% |
| 0.5 Hz | 1.07% | 0.97% | 1.09% | 1.26% |
| 1 Hz | 6.30% | 1.93% | 1.95% | 1.90% |
| 2 Hz | 27.65% | 10.99% | 8.73% | 5.61% |
| 3 Hz | 25.19% | 20.95% | 20.22% | 12.26% |

- 早期 0.5 Hz / 0.35 Nm 参考速度 0.5 rad/s 时 RMSE 约 12.03%；提高到 1.5 rad/s 后
  两轮平均约 1.36%，支持先前参考限速不足的判断。
- 高频轮原生收发约 100 Hz，最大反馈间隔约 19.1 ms，记录无故障；机械跟随仍明显下降。
- 0.35 Nm / 2 Hz 的逐周期中心约从 0.669 漂到 0.808；0.9 Nm / 3 Hz 也有中心漂移。
  这是待解决现象，不能将结果直接当作电机本体带宽。
- 温度约 33℃、固件包络额度 2 Nm；这只是该设备本次记录，不是固件默认值。
  没有热保护主导本轮性能下降的证据，也没有测出电机可持续最大扭矩。

电机编码器不是独立爪尖位置测量；电机估计扭矩不是夹持力测量。
空行程结果不能证明真实持物、抗滑、双爪一致性或极限温度下的效果。

## 4. SDK 仍需要改什么

按当前遥操 / 推理需求排序；下表是建议与验收要求，**不是已实现功能**。

| 优先级 | 问题 / 建议 | 完成的判断标准 |
|---|---|---|
| P1 | 高频低预算中心漂移：记录真实参考、P/D 项及 SDK 裁剪，再修正预算分配 / 换向参考 | 在相同轨迹与预算回放中无持续中心漂移，误差可解释；受阻和反向释放不退化 |
| P1 | 应用目标超时独立于 MCU 通讯超时：在原生运行时识别模型停止更新 | Python 生产者停更而通信线程存活时，按明确的保持 / 失能策略处理，并报告原因；不自动恢复 |
| P1 | 运动瞬态预算与静止夹持预算在客户接口中分开 | 可以独立配置，固件仍为最终上限；模式 / 目标频繁切换不重置热历史；经负载 / 热验证 |
| P1 | 诊断清楚报告 SDK、固件和电机分别限制了什么 | 能区分参考限速、P/D 预算裁剪、静止降额、温度、启动限扭；不能只给 `target_limited` 总标志 |
| P2 | SDK / 固件发布物统一 | 明确版本矩阵、新版镜像、哈希、来源、fresh-host 安装验证，防止读源码却运行旧 wheel |
| P2 | `grasp` / `impedance` 默认参数与连接默认值的继承规则统一 | 客户不用记住三套默认规则，同时有兼容迁移说明 |
| P2 | 状态语义进一步收敛 | 清楚区分在线、命令已提交、正在执行、到位和接触；流式目标下 `ready` 不易误读 |
| P2 | 目标时间戳与模型动作集成 | 有明确的动作时钟、跳过过期点策略与非阻塞样例；不是把 Python 调用率当执行率 |

不建议现在只把 1.2 Nm 上限调到 5.5 Nm：这会把协议量程误当机构工作额度，
也无法单独解释 / 修复中心漂移。更合适的是在既有固件保护下分开运动与保持预算，
并提供限制原因；当前控制策略没有在本次文档整理中改动。
