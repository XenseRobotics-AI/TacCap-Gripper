# 面向遥操与模型推理的夹爪 SDK

客户主循环只需要持续给定目标开口并读取状态。离散 grasp/release 语义保留兼容，
不再作为默认使用路径。此前位置受阻会锁存并将输出改为当前位置，这会撤去夹持力矩，
也会造成张开被提前截停；本版取消该策略。接触估计不能取消位置控制意图。

| 层 | 责任 |
|---|---|
| Python Gripper | 设备选择、默认预算、参数校验、set_position/state/timing、旧接口兼容 |
| 原生策略 | 最新目标、速度参考及前馈、限扭位置跟随、补偿、专业 grasp/impedance 模式 |
| 原生运行时 | 一个控制权、反馈订阅、每帧最多一次输出、序号与时间统计、停止和释放资源 |
| 固件 | 500 Hz 名义执行、实际反馈检查、持续/瞬态限扭、温度保护、500 ms 通信超时和故障锁存 |

上层目标以 latest-value 方式更新，不构建积压队列。不因目标重复或接触推断改变
位置意图；只有新目标、显式 hold/disable、故障或退出能改变当前任务。
位置误差可在遇到物体后持续存在，不能承诺“穿过物体到位并夹紧”。

SDK 对固件 1.1.7 的兼容路径仍使用同步执行状态查询。固件 1.1.8 协商扩展状态流，
将原始电机位置、CAN 样本年龄和执行状态合入一帧，避免高频线程等待额外 ACK。
频率上限保持原有 100 Hz，先解决抖动和可观测性，再以实测决定是否扩频。

背隙补偿是显式、默认关闭的闭合偏移，按开口线性淡出，保留最大张开端点。
SDK 提供 0..0.05 rad 参数；固件约束 MIT 位置补偿余量，并保留原有扭矩保护。
当前用户估计 0.03 rad，不是自动辨识结果。它不等价于全行程双向迟滞补偿。

持续输出保护放在固件：停转时间窗缩小峰值余量，运动时仍累计 I²t，温度墙独立生效。
时间窗不受主机目标更新频率影响，热历史不随模式切换重置。
具体接口、默认值、兼容行为和测量边界见 [使用说明](../USAGE.md)。

## 验证要求

软件测试覆盖持续受阻仍有闭合/张开力矩、重复目标、反向目标、20/50/100 Hz 策略步长、
预算约束、0.03 rad 正反安装补偿、被覆盖命令不排队、扩展状态缺失/陈旧/报错、
旧固件与旧接口兼容。固件纯策略测试覆盖同毫秒重复计算、停转降额、移动 I²t、
短暂移动、未知长间隔、时钟回绕和补偿边界。

已有用户设备的空夹爪位置轨迹、控制/上报频率和间隔记录，见[当前状态](../STATUS.md)。
仍需验证不同物体夹持、反向释放、低电压、温度和通信失联停止，并解决高频中心漂移。
主机提交延迟不冒充端到端响应；电机位置/扭矩也不冒充爪尖开口/夹持力。
