# 当前 SDK / 固件控制契约

适用：SDK 0.2.0b1、从爪固件 1.1.8；1.1.7 保留兼容路径。
用户流程见[使用手册](../USAGE.md)，实测与未完成项见[当前状态](../STATUS.md)。
旧 1.1.6 实验已移至[历史记录](../history/CONTROL_LAYERING_1_1_6.md)，其中旧数值不用于当前配置。

## 1. 责任与唯一入口

| 层 | 负责 | 不负责 |
|---|---|---|
| 应用 / 模型 | 目标开口、动作时间戳、应用过期策略、任务成功判断 | 直接周期写设备寄存器 |
| Python `Gripper` | 选择设备、校验参数、归一化意图、结果与状态、统一生命周期 | 电机内部伺服、爪尖力测量 |
| 原生控制策略 | 最新目标、位置参考 / 预算、闭合偏移、显式 grasp / impedance | 最终硬件额度、热安全认证 |
| 原生 `ControlRuntime` | 单对象控制权、反馈驱动刷新、订阅、计数、停止和资源释放 | 跨进程串口互斥、模型目标是否过期 |
| MCU 固件 | 上电归零 / 标定、外部目标校验、2 ms 名义执行、动态包络、反馈检查、失联 / 故障锁存 | 理解模型任务、判断物体夹稳 |
| RS05 电机 | 内部伺服与 CAN 指令执行、内部参数约束 | 主机应用生命周期 |

位置控制调用链：

```text
模型 / 遥操的 0..1 开口
  -> Gripper.set_position / move
  -> ForcePositionController.set_position_target（POSITION 分支）
  -> 参考位置 + 参考速度 + SDK 预算裁剪
  -> ControlRuntime：每条新反馈后至多提交一次，最新值覆盖
  -> MotorImpedanceCtrl / MIT 五参数串口命令
  -> MCU 外部目标调度与包络
  -> RS05 MOTION（run_mode=0）
```

客户方法叫 position，不意味着电机使用厂商 PP 模式。
原生旧 `set_target()` 是接触策略，不能仅按 `ForcePositionController` 类名判断当前控制方式。

## 2. 位置与夹持语义

位置模式保留目标，受阻也继续按预算朝目标施力；新目标可直接反向释放。
不因接触推断锁存当前位置，也不自动切纯前馈保持。目标小于物体开口时不能到位，
但可以持续有界施力；这与到位结果不同。

显式 `grasp` 才使用闭合接触估计 / 纯前馈保持；`impedance` 是持续 PD / 前馈目标。
`hold` 改为当前原始电机位置，不保证维持此前的压紧力。
`stop/disable/close` 请求失能；等待超时本身不失能。

SDK 位置策略基础 Kp=20、Kd=1；速度项与位置误差共享预算。
当前算法在部分高频低预算轨迹出现中心漂移，可能与预算分配 / 换向参考有关，
尚无完整下发 P/D 日志证实根因；本次未更改该策略。

## 3. 三层力矩约束

| 约束 | 当前含义 |
|---|---|
| 客户 `torque_limit_nm` | 请求预算，上限 1.2 Nm；连接默认 0.35 Nm |
| 原生配置 | motion 最大 5.5 Nm，hold 最大 1.2 Nm；不是客户默认请求 |
| 固件包络 | 未配置时 RAM cont=1.0 / peak=1.5 Nm；有效持久化记录可不同 |
| 电机启动 `0x700B` | 存于 MCU Flash、启动时应用到电机；独立额度，可能低于原生 motion 上限 |

RS05 协议力矩量程按说明书采用 ±5.5 Nm、位置 ±12.57 rad；协议量程不是推荐工作点。
旧 1.8 Nm 转动额定条件不能用于无限期堵转承诺；静止输出也取决于实际散热。
已启用包络必须满足布局版本 2、`0 < cont <= 1.2`、`cont <= peak <= 5.5`，
无效记录拒绝外部运动；未配置 / 未启用记录使用 RAM 默认，不能推断为无保护。

固件对外部位置、速度、力矩和 MIT 模式统一约束；MIT 在当前反馈上计算
`|Kp × 位置误差| + |Kd × 速度误差| + |前馈扭矩|`，超额时缩小增益 / 前馈。
这不是采样间真实机械力矩的硬保证。纯力矩 / 纯前馈额外不超过连续额度。
私有 CAN 协议不支持的阻抗请求明确拒绝。

`state.effective_torque_limit_nm` 是 MCU 包络额度，可能高于本次 SDK 请求；
`target_limited` 是固件对目标的变换总标志，不能直接解释为热降额。

## 4. 停转时长、温度与补偿

1.1.8 按反馈速度以 0.05 / 0.10 rad/s 滞回判定停转 / 移动。
停转累计 200 ms 后，接下来 300 ms 缩小峰值余量至连续额度；短暂移动逐步恢复，
不会立即清空。移动时也累计负载 I²t，温度约束独立生效。
热历史不随命令、模式、失能、清错重置；重启会失去软件历史，不等于已冷却。
已有 90/100℃ 温度策略仍需实机验证，这些是工程配置，不是厂家持续时间保证。

可选闭合补偿 `0..0.05 rad` 仅沿闭合端增加余量，按 `1-position` 淡出；
最大张开端不扩展，不修改保存标定。客户默认关闭；当前设备显式试用 0.03 rad。
依赖 1.1.8 原始电机位置反馈，避免旧 0..1 截断丢失闭合越零信息。
这不构成通用双向背隙模型。

## 5. 频率与可观测性

SDK 支持 20/25/40/50/100 Hz，默认 100 Hz；模型输出频率独立。
MCU 外部调度为名义 2 ms / 500 Hz，不提高主机新目标的产生频率。
时间统计分别记录反馈、串口提交、主机 API→UART 耗时，不能冒充机械端到端时延。

1.1.8 用 `StartStream.source_mask=0x30` 协商 107B 电机流：
31B 旧状态 + 68B 执行状态 + 4B CAN 样本年龄 + 4B 原始电机位置。
旧 `0x10` 仍为 31B；1.1.7 通过同步查询 0x56 兼容，会增加抖动。
执行状态与电机状态不是原子事务，无法精确证明某个 SDK 命令已在电机执行。

`motor.execution_status()` 查询 0x56，返回 owner、home / envelope 状态、
target/applied 序号、错误、requested/applied 的 pos/vel/torque/kp/kd 和额度。
applied 是最近下发的量化前参数，不是实测输出；停止后也可能保留。
固件完整布局见固件仓库 `docs/CONTROL_SAFETY.md`。

## 6. 超时、所有权与恢复

**MCU 连续 500 ms 未收到有效运动目标 → 请求失能、锁存故障，可能释放物体。**
重复目标可以续期，读取状态不能续期。SDK 持续控制器负责刷新，应用目标值可以暂时不变。
模型停止更新但 SDK 仍刷新时不会触发此超时；应用目标过期目前由应用负责。

MCU 检查电机反馈有限值、故障和 150 ms 新鲜度；客户运行时反馈超时为 350 ms。
失能 CAN 发送失败时固件保留锁存并重试；清错不能撤销未完成的失能请求。
处理原因后显式清错，再给新目标；不自动恢复旧动作。

MCU 主机超时不覆盖 MCU 停摆或 CAN 断线后电机继续执行旧帧；当前未配置电机侧
`0x7028` CAN timeout。归零也是独立固件流程，不能声称外部目标入口覆盖其全部保护。

运行时保护同一原生 Motor 的控制权与订阅生命周期；其他进程 / 直接 Transport 写入不在
该对象互斥范围。客户控制、原生控制器、GUI 和 OTA 不应同时控制同一设备。
